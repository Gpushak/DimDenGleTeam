## Тема проекта

«АСУ складского учёта с весовым модулем и QR-идентификацией»

## Задачи

**Сборка и программирование весового модуля на Arduino** — тензодатчик и HX711 (GPIO), передача данных о весе на Linux-ПК через Serial-порт.

**Разработка десктопного приложения на Linux** — генерация QR-кодов для товаров, печать этикеток, управление справочником товаров.

**Построение REST API на FastAPI** — связь между весовым модулем, десктопом и мобильным приложением, хранение данных в SQLite.

**Создание Android-приложения** — создание и управление списками товаров, добавление и удаление позиций путём сканирования QR-кодов, синхронизация с сервером.

## Ожидаемый результат

Работающий прототип системы, позволяющий администратору генерировать QR-этикетки на ПК, кладовщику — взвешивать товары и управлять списками через мобильное приложение, задокументированный API (Swagger), отчёт о тестировании.

## Запуск через единый docker-compose

В корне репозитория находится `docker-compose.yml`, который запускает все контейнеризуемые сервисы проекта:

```bash
cp .env.example .env      # при необходимости скорректируйте порты/устройства
docker compose up --build # REST API доступен на http://localhost:8000 (Swagger: /docs)
```

| Сервис | Profile | Описание |
|--------|---------|----------|
| `api` | (по умолчанию) | FastAPI + SQLite, том `warehouse-data` для БД, healthcheck `/health` |
| `scale-emulator` | `scale` | Эмулятор весового модуля (Serial-порт Arduino/HX711 → API) |

Десктопное приложение (`desktop/`) в Docker **не запускается** — это GUI, которому
нужна графическая сессия хоста. Запускается нативно (см. `desktop/README.md`).

Веб-клиент (`web/`) повторяет функции десктопа в браузере (Vue, TypeScript, Pinia).
В Docker не входит, запускается через `npm run dev` (см. `web/README.md`).

Запуск опциональных сервисов — через profiles, например:

```bash
docker compose --profile scale up --build
```

Android-приложение в Docker не запускается: APK собирается из папки `android/` и по умолчанию обращается к серверу (`http://<IP-хоста>:8000`).

Как указать Android-приложению адрес сервера:
- **Эмулятор Android** — адрес хост-машины `http://10.0.2.2:8000/` (используется по умолчанию);
- **Реальный телефон в той же Wi-Fi сети** — IP компьютера с сервером, например `http://192.168.1.50:8000`. Сервер запущен на `0.0.0.0`, CORS открыт; порт 8000 должен быть разрешён в брандмауэре. Адрес можно задать:
  - прямо в приложении: кнопка **«Сервер»** на главном экране (сохраняется между запусками);
  - при сборке: `./gradlew assembleDebug -PapiHost=192.168.1.50 -PapiPort=8000` (или переменные окружения `API_HOST` / `API_PORT`).

Путь к базе данных внутри контейнера задаётся переменной `WAREHOUSE_DB` (по умолчанию `/data/warehouse.db`, примонтирован volume). При локальном запуске без Docker используется `server/data/warehouse.db`.

## Эмулятор весового модуля (scale-emulator)

Эмулятор весового модуля (`firmware/weight_module/emulator.py`) предназначен для тестирования весового контура без физического железа. Он работает в двух режимах:

1. **Serial** — если задан `SERIAL_PORT` (и установлен pyserial), читаем строки от Arduino и публикуем распарсенный вес.
2. **Simulation** — если порт не задан или недоступен, генерируем правдоподобный вес (эмуляция работы кладовщика).

### Запуск эмулятора

**Рекомендуемый способ (Docker):**
```bash
docker compose --profile scale up --build
```

**Локальный запуск (для разработки):**
```bash
cd firmware/weight_module
python emulator.py
```

**Внимание:** При локальном запуске эмулятора установите переменную окружения `API_BASE_URL`, чтобы указать адрес API:

```bash
# Для локального API (если сервер запущен на хосте)
export API_BASE_URL="http://127.0.0.1:8000"

# Для Docker API (если сервер запущен в контейнере)
export API_BASE_URL="http://api:8000"
```

### Распространённые проблемы и решения

**Проблема:** При локальном запуске эмулятора возникает ошибка:
```
API недоступен (http://api:8000) — эмулятор ожидает API по адресу 'http://api:8000', который является Docker-internal hostname.
Если вы запускаете эмулятор на хосте, установите переменную окружения API_BASE_URL,
например, API_BASE_URL=http://127.0.0.1:8000. Если вы хотите использовать Docker,
запустите эмулятор через 'docker compose --profile scale up -d scale-emulator'
```

**Решение:** Установите правильный адрес API в переменной окружения `API_BASE_URL`.

**Проблема:** Эмулятор не может подключиться к API, потому что сервис `api` не запущен.

**Решение:** Убедитесь, что сервис `api` запущен:
```bash
docker compose up --build
```

**Проблема:** Эмулятор не может подключиться к API, потому что порт API закрыт брандмауэром.

**Решение:** Откройте порт 8000 в брандмауэре хоста или используйте VPN (Tailscale) для доступа к серверу.

### Настройки эмулятора

Эмулятор использует следующие переменные окружения:

| Переменная | Описание | Значение по умолчанию |
|------------|-----------|---------------|
| `API_BASE_URL` | Адрес REST API | `http://api:8000` (Docker) или `http://127.0.0.1:8000` (хост) |
| `SERIAL_PORT` | Serial-порт Arduino | пусто (веса берутся из API) |
| `SERIAL_BAUD` | Baud-рейт Serial-порта | `9600` |
| `PUBLISH_INTERVAL` | Интервал публикации в секундах | `1.0` |
| `SIM_MIN_WEIGHT` | Минимальный вес для симуляции | `0` |
| `SIM_MAX_WEIGHT` | Максимальный вес для симуляции | `2500` |

### Пример запуска эмулятора с симуляцией весов в диапазоне 100–500 г:

```bash
export API_BASE_URL="http://127.0.0.1:8000"
export SIM_MIN_WEIGHT="100"
export SIM_MAX_WEIGHT="500"
python firmware/weight_module/emulator.py
```

### Пример запуска эмулятора с реальным Serial-портом:

```bash
export API_BASE_URL="http://127.0.0.1:8000"
export SERIAL_PORT="/dev/ttyUSB0"
export SERIAL_BAUD="9600"
python firmware/weight_module/emulator.py
```

## Доступ к серверу извне (Tailscale)

Сервер развёрнут на `asu-23gddprojserver` (Ubuntu 26.04, Docker). Доступ к нему
из локальной сети — по адресу `http://192.168.0.9:8000`. Чтобы разработчики
Android и десктопа могли работать с сервером **из любой сети** (не обязательно
рядом с ним), используется **Tailscale** — приватная VPN-сеть (tailnet). Сервер
при этом **не выставлен в интернет**: к нему могут подключиться только участники
tailnet, поэтому аутентификация API не требуется.

Адреса сервера в tailnet:

| Что | Значение |
|-----|----------|
| Tailscale IP | `100.95.192.75` |
| MagicDNS-имя | `warehouse-server.tail96180b.ts.net` |

### Что сделать разработчику (Android / десктоп)

1. Установить Tailscale: https://tailscale.com/download (Windows / Linux / Android — есть в Play Store).
2. Войти в tailnet тем же аккаунтом, что и у сервера.
3. Проверить доступ: открыть `http://warehouse-server.tail96180b.ts.net:8000/docs` (Swagger) — должна загрузиться документация API.

После этого указать адрес в клиенте:
- **Android**: при сборке `./gradlew assembleDebug -PapiHost=warehouse-server.tail96180b.ts.net -PapiPort=8000`, либо прямо в приложении — кнопка **«Сервер»** на главном экране (адрес сохраняется между запусками).
- **Десктоп**: переменная окружения `API_BASE_URL=http://warehouse-server.tail96180b.ts.net:8000` (подробнее — `desktop/README.md`).

### Состояние сервера

- `tailscaled` — служба systemd, включена автозагрузка (`enabled`), поднимается при загрузке Ubuntu.
- Контейнер `warehouse-api` — политика перезапуска `unless-stopped`.
- Docker-том `warehouse-data` хранит БД (`/data/warehouse.db`) и переживает пересборку образа.

### Обслуживание (на сервере)

```bash
ssh gustavo@192.168.0.9
cd ~/warehouse-server

docker compose ps                 # статус
docker compose logs -f api        # логи API
docker compose up -d --build      # пересобрать и применить изменения
docker compose --profile scale up -d   # добавить эмулятор весов
docker compose down               # остановить

sudo tailscale status             # состояние VPN
sudo systemctl restart tailscaled # перезапустить VPN
```
