## Тема проекта

«АСУ складского учёта с весовым модулем и QR-идентификацией»

## Задачи

**Сборка и программирование весового модуля на Arduino** — тензодатчик и HX711 (GPIO), передача данных о весе на Linux-ПК через Serial-порт.

**Разработка десктопного приложения на Linux** — генерация QR-кодов для товаров, печать этикеток, управление справочником товаров.

**Построение REST API на FastAPI** — связь между весовым модулем, десктопом и мобильным приложением, хранение данных в SQLite.

**Создание Android-приложения** — создание и управление списками товаров, добавление и удаление позиций путём сканирования QR-кодов, синхронизация с сервером.

## Ожидаемый результат

Работающий прототип системы, позволяющий администратору генерировать QR-этикетки на ПК, кладовщику — взвешивать товары и управлять списками через мобильное приложение, задокументированный API (Swagger), отчёт о тестировании.

## Запуск через единый docker-compose

В корне репозитория находится `docker-compose.yml`, который запускает все контейнеризируемые сервисы проекта:

```bash
cp .env.example .env      # при необходимости скорректируйте порты/устройства
docker compose up --build # REST API доступен на http://localhost:8000 (Swagger: /docs)
```

| Сервис | Profile | Описание |
|--------|---------|----------|
| `api` | (по умолчанию) | FastAPI + SQLite, том `warehouse-data` для БД, healthcheck `/health` |
| `scale-emulator` | `scale` | Эмулятор весового модуля (Serial-порт Arduino/HX711 → API) |
| `desktop` | `desktop` | Десктопное приложение (QR-коды, этикетки, справочник) |

Запуск опциональных сервисы — через profiles, например:

```bash
docker compose --profile scale up --build
```

Android-приложение в Docker не запускается: APK собирается из папки `android/` и указывает на `http://<IP-хоста>:8000`.

Путь к базе данных внутри контейнера задаётся переменной `WAREHOUSE_DB` (по умолчанию `/data/warehouse.db`, примонтирован volume). При локальном запуске без Docker используется `server/data/warehouse.db`.
