# Десктопное приложение складского учёта

GUI-клиент для склада: дерево контейнеров, таблица товаров, CRUD-операции,
QR-этикетки, отображение веса с весового модуля.

## Стек

- **Python 3.11+**
- **GUI**: customtkinter (тёмная тема)
- **Данные**: REST API (FastAPI-сервер из папки `server/`)
- **Тесты**: unittest (без внешних зависимостей)

Приложение **не обращается к SQLite напрямую** — единственный источник данных
для десктопа, Android и весового модуля это REST API.

## Установка и запуск

### 1. Поднять API

Из корня репозитория:

```bash
docker compose up --build     # http://localhost:8000
```

или локально:

```bash
cd server
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 2. Запустить десктоп

```bash
cd desktop
pip install -r requirements.txt
python main.py
```

Зависимости: `customtkinter` (UI), `pyserial` (чтение весов), `qrcode[pil]`
(генерация QR-кодов).

## Тесты

Логика десктопа покрыта тестами без графической оболочки и без сервера —
`BoxIndex` и фильтрация товаров проверяются на подставных данных:

```bash
python -m unittest discover -s desktop -t desktop
```

Тесты: `desktop/test_crud.py`.

## Настройка

| Переменная | Назначение | По умолчанию |
|------------|------------|--------------|
| `API_BASE_URL` | Адрес REST API | `http://127.0.0.1:8000` |
| `SERIAL_PORT` | Порт Arduino с весами | пусто (веса берутся из API) |

Пример:

```bash
API_BASE_URL=http://192.168.1.50:8000 SERIAL_PORT=/dev/ttyUSB0 python main.py
```

Если `SERIAL_PORT` не задан или `pyserial` не установлен, приложение раз в
секунду опрашивает `GET /scale` — это позволяет получать вес, опубликованный
эмулятором весов из Docker.

## Архитектура

```
main.py ──┬── ui/main_window.py ──┬── crud.py ──── api_client.py ── HTTP
          │                       │
          │                       └── models.py (датаклассы)
          └── scale.py (Serial/GET /scale)
```

Правила, которых стоит держаться:

1. **Единственный источник данных — REST API.** `desktop/` не открывает SQLite.
2. **UI не знает про HTTP.** Диалоги вызывают `crud.*` и ловят исключения.
3. **`database.py` — только настройки**, несмотря на имя.
4. **Контейнеры грузятся один раз на перерисовку** — см. `BoxIndex` ниже.

### Кэш контейнеров (BoxIndex)

Путь контейнера («Склад / Стеллаж A / Полка 1») требует знания всей цепочки
родителей, то есть всего ответа `/boxes`. Наивная реализация делала бы запрос
на каждую строку таблицы. Вместо этого `crud.BoxIndex` загружает контейнеры
**один раз** и кэширует вычисленные пути:

```python
boxes = crud.BoxIndex.load(client)
location = boxes.full_path(item.box_id)   # дополнительных запросов: 0
```

Итог: перерисовка таблицы из 500 позиций — это 2 запроса (`/boxes` + `/items`),
а не 1001.

## Функциональность

### Управление контейнерами (дерево слева)
- Добавление контейнера с выбором типа и родителя
- Редактирование, включая смену родителя (с защитой от циклов)
- Удаление: потомки удаляются каскадно, товары переходят в «Без расположения»
- Иерархическое отображение с раскрытием/сворачиванием узлов

### Управление товарами (таблица справа)
- Создание, редактирование и удаление
- Колонки: тип, количество, вес, расположение (полный путь)
- Сортировка по клику на заголовок (с учётом «1.50 кг» → граммы и натуральной
  сортировки чисел в именах)

### Типы товаров
- Создание и редактирование типов с указанием веса одного экземпляра
- Вес используется для расчёта суммарного веса позиций

### Поиск
- По названию типа товара и по расположению

### Разделы
- **Все товары** — все записи
- **Без расположения** — товары с `box_id = NULL`
- Конкретный контейнер — товары в контейнере и всех потомках

### QR-этикетки
Кнопка **QR** формирует QR-код для выбранного товара в формате
`qwentory:item:<item_id>`. Сервер разбирает такие коды через
`GET /lookup?code=...`, Android-приложение сканирует их камерой.

### Весы
Если задан `SERIAL_PORT`, приложение читает строки `WEIGHT:<граммы>` с Arduino
и публикует их в `POST /scale`. Текущий вес отображается в строке статуса,
таблица обновляется при изменении показания (через публичный `refresh_items`).

## Модель данных

Схема хранится в `server/db/schema.sql`:

- `box_type` (`box_type_id`, `box_type_name`)
- `box` (`box_id`, `box_name`, `box_type_id` → FK, `parent_id` → self FK)
- `item_type` (`item_type_id`, `item_type_name`, `weight_g`)
- `item` (`item_id`, `item_type_id` → FK, `box_id` → FK nullable, `quantity`)

## Демо-данные

При первом запуске API создаёт БД из `server/db/schema.sql` и заполняет её
демо-данными: 8 типов контейнеров, 10 контейнеров в иерархии, 8 типов товаров
и 8 записей товаров. Чтобы пересоздать базу — остановите API, удалите том
`warehouse-data` (или файл `server/data/warehouse.db` при локальном запуске)
и запустите снова.
