# Android-приложение складского учёта

Мобильный клиент Warehouse API: просмотр структуры склада и **сканирование
QR-кодов** для получения сведений о товаре, типе товара или контейнере.

## Стек

- Java 17, Android SDK 34 (minSdk 24)
- Retrofit + OkHttp + Gson
- CameraX + ML Kit Barcode Scanning
- View Binding

## Сборка

```bash
./gradlew assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`

## Настройка адреса сервера

По умолчанию `http://10.0.2.2:8000/` — адрес хост-машины из эмулятора Android.

Способ 1 — при сборке:

```bash
./gradlew assembleDebug -PapiHost=192.168.1.50 -PapiPort=8000
```

Способ 2 — переменные окружения `API_HOST` / `API_PORT` (читаются в
`app/build.gradle`).

Способ 3 — прямо в приложении: кнопка **«Сервер»** на главном экране. Адрес
сохраняется в `SharedPreferences` и переживает перезапуск; кнопка **«Сбросить»**
возвращает значение из `BuildConfig`.

> Сервер работает без аутентификации, токен не требуется.

## Экраны

### Главный экран (`MainActivity`)

Дерево контейнеров склада: тап по корню открывает список вложенных контейнеров
и товаров, «↑ Вверх» поднимается на уровень выше, `path`-строка показывает
текущее положение. Свайп вниз обновляет дерево.

### Сканирование QR-кодов (`ScanActivity`)

Кнопка **«QR-сканер»** на главном экране открывает камеру со сканированием.
Распознанный код отправляется на сервер, результат показывается диалогом:

| Код | Что покажет |
|-----|-------------|
| `qwentory:item:<id>` | Тип товара, количество, вес единицы и общий, расположение, ID позиции |
| `qwentory:type:<id>` | Справочная запись типа товара: название, вес единицы, ID |
| `qwentory:box:<id>` | Тип контейнера, список товаров с количеством и весом, вложенные контейнеры |

После сканирования товара или контейнера приложение возвращает
`MainActivity` найденный `box_id`/`item_id` и само переходит в нужный
контейнер, пересобирая путь по иерархии.

Особенности реализации:

- `ImageAnalysis.STRATEGY_KEEP_ONLY_LATEST` — обрабатывается только последний
  кадр, иначе очередь кадров растёт без пользы;
- `AtomicBoolean` защищает от параллельного распознавания;
- кулдаун 1.2 с и флаг запроса не дают отправлять десятки одинаковых
  запросов, пока код остаётся в кадре;
- при отсутствии разрешения на камеру (или если камера не запустилась)
  показывается кнопка **«Ввести код вручную»** — она пригодится и при
  разработке без реального QR-кода;
- `scanner.close()` и `executor.shutdown()` в `onDestroy`.

## Формат QR-кодов

Коды генерирует десктопное приложение (`desktop/qrutil.py`), формат задан
в `shared/protocol.py` и разбирается сервером в `GET /lookup`:

```
qwentory:item:<item_id>      — позиция товара
qwentory:type:<item_type_id> — тип товара
qwentory:box:<box_id>        — контейнер
```

Класс `QrCode` проверяет формат на клиенте, чтобы не тратить запросы на
чужие QR-коды (обычные товарные штрихкоды и т.п.).

## Эндпоинты

| Метод | Путь | Назначение |
|-------|------|------------|
| GET | `/boxes/tree` | Дерево контейнеров |
| GET | `/boxes/{id}/contents` | Содержимое контейнера |
| GET | `/lookup?code=<QR>` | Разбор QR-кода |

## Разрешения

`CAMERA`, `INTERNET`, `ACCESS_NETWORK_STATE` — объявлены в `AndroidManifest.xml`.
`usesCleartextTraffic="true"` разрешает HTTP к адресу в локальной сети
(для продакшна нужен HTTPS).
